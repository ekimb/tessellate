# `tessellate`: genomic tessellations
A **tessellation** is a covering of a plane with a finite set of patterns, or _tiles_, derived from a single shape such
that the tiles intersect only on their boundaries with no overlaps and no gaps.  In Roman _opus tessellatum_, individual _tesserae_
were assembled into decorative and figurative compositions. Escher’s study of the interlocking motifs in The Alhambra inspired a series of pieces known as Escher’s tilings:

<p align="middle">
  <img src="https://i.pinimg.com/736x/62/22/3e/62223ef5a2ebc54e9e53672e18da6c6a.jpg" width="200" />
  <img src="https://static.wixstatic.com/media/86a060_292d9242542f42a4bd2a1936b6cf8554~mv2.jpeg/v1/fit/w_500,h_500,q_90/file.jpg" width="230" /> 
</p>

where repetition acts along one coordinate: translating by the length of a unit reproduces the same periodic template. Beginning the interval halfway through the unit changes its phase (or _geometry_), while retaining its cyclic _identity_. 

`tessellate` rewrites DNA sequences as a sequence of _tiles_: maximal stretches that are (approximately) periodic in a unit of period 1–7 (`A`, `CA`, `AAT`, `TTAGGG`, ...), matched within a small budget of edits. Every tile is stored as its canonical _identity_, and the auxiliary information about its identity (length, phase, edits) is stored on disk as _geometry_.

## Build

```sh
cargo build --release
```

The binary is `target/release/tessellate`. The build targets `x86-64-v4` (AVX-512; set in `.cargo/config.toml`) and generates the edit-budget table `budgets.bin` at build time (~30 s on first build).

## Toy example

`example/` holds a small simulated data set, generated by `example/simulate.py` (deterministic, seed 7):

| File | Contents |
|---|---|
| `example/truth.fa` | two _true_ chromosomes (`chr1` 33kb, `chr2` 26kb) with microsatellites (`CA`, `AAT`, `GATA`, `AGG`, `TTAGGG`) and a 4kb segmental duplication shared by both, 0.3% diverged |
| `example/ref.fa` |  _assembly_: `truth.fa` with three microsatellite length errors planted (chr1 `(CA)40`→`(CA)37`, chr1 `(AAT)30`→`(AAT)32`, chr2 `(AGG)35`→`(AGG)33`) |
| `example/read.fa` | 222 HiFi-like reads (6–10kb, 0.3% errors, ~30× coverage, both strands) sampled from `truth.fa`; each header records its true origin, e.g. `>read1 chr1:15339-25310-` |

Run the whole pipeline from the repository root:

```sh
T=target/release/tessellate

# 1. tessellate sequences
$T fastx -i example/ref.fa                # -> example/ref.tq.gz, example/ref.tss (+ .tqi, .tsi indexes)
$T fastx -i example/read.fa               # -> example/read.tq.gz, example/read.tss

# 2. index the assembly
$T bwt -i example/ref.tq.gz               # -> example/ref.tbwt

# 3. repeats in the assembly, then read evidence over it
$T hom -i example/ref.tbwt -o example/ref.hom                                   
$T hom -i example/ref.tbwt -o example/read.hom example/read.tq.gz
$T hom -i example/ref.tbwt -o example/read.trace.hom --trace example/read.tq.gz

# 4. map reads
$T map -i example/ref.tbwt -o example/read.map.tsv example/read.tq.gz

# 5. polish the assembly with the read evidence
$T polish --detect example/read.hom --decide example/read.trace.hom \
  --reads example/read.tq.gz --index example/ref.tq.gz --fasta example/ref.fa \
  -o example/ref.polished.fa --edits example/ref.edits.tsv --windows example/ref.windows.tsv
```

On the toy example in `example/`,

- `hom` finds the segmental duplication: the `R` rows of `example/ref.hom` pair `chr1:~11.1–15.1 kb` with `chr2:~11.1–15.1 kb`, and `D` rows list the tiles where the two copies differ.
- `example/read.hom` has a `T` row over the planted `(CA)37` error at `chr1:6000`, where all reads disagree with the assembly (`agree` 0 of depth 28) and shows that the tile spans 79bp instead of 73bp (`S:79:73`).
- `map` places every read at its true origin (`best` row, MAPQ 60); reads from the segmental duplication also get a `secondary` row on the other copy.
- `polish` makes exactly the three planted fixes; `example/ref.polished.fa` is identical to `example/truth.fa`.

Generated files in `example/` are ignored by git; regenerate the inputs with `cd example && python3 simulate.py`.

## Subcommands

All subcommands take `-t/--threads` (default 8). Progress goes to `stderr`.

```
tessellate fastx -i <in.fa> [-i <more.fa> ...] [-o <prefix>] [-d <0..8>] [-r <rate>]
```

reads FASTA/FASTQ (plain or `gzip`/`bgzip` compressed) and parses every record into tiles, allowing up to `-d` edits (default 1) inside a tile, and outputs BGZF-compressed **tile identity** in `<prefix>.tq.gz`: per record, its name and the canonical identity of each tile, with index `<prefix>.tq.gz.tqi`, and BGZF-compressed **tile geometry**: per tile, its phase, length and edits, i.e., everything needed to reconstruct the exact bases from the `.tq.gz` identity, in `<prefix>.tss`, block-sampled every `-r` tiles (default 32) for random access with index `<prefix>.tss.tsi`.

```
tessellate bwt -i <ref.tq.gz> [-o <prefix>] [-r <rate>]
```

builds a bidirectional FM-index over the tile sequences of every record, on both strands, with locate samples every `-r` tiles, and outputs `<prefix>.tbwt` (default `<prefix>` = input stem). The index records the path of its source `.tq.gz`/`.tss`.

```
tessellate hom -i <ref.tbwt> [-o <report>] [-k <tiles>] [-O <occ>] [--frac <f>]
               [-p <ploidy>] [-g <tiles>] [--min <w>] [--trace | --trace-bed <bed>] [reads.tq.gz ...]
```

loads or otherwise creates `<ref>.trep`, the _autotessellation_ of the assembly. Every super-maximal exact match (SMEM) of at least `-k` tiles (default 31) with at most `-O` occurrences (default 0 = unlimited) becomes a correspondence. `--frac` (default 0.05) sets the containment threshold for contig families. An existing `.trep` is reused as is. If read `.tq.gz` files are given, seeds every read against the index with SMEMs and lets each read vote on whether it agrees with the assembly's tile otherwise provide alternative tiles. SMEMs with more than `-p` occurrences (default 2) do not vote. `hom` outputs a `TAB`-separated report to `-o` (default `stdout`). Each row type has a `#`-prefixed header line in the report:

| Row | Meaning |
|---|---|
| `C` | per contig: length, tiles, read depth, whether it is contained in another contig, and links from its ends |
| `F` | contig families (contigs grouped by shared sequence) |
| `R` | one per repeat group: location of the first copy and every copy as `contig:tile:base:strand:ndiff` (with reads, plus depth/support and left/right `through/other/orphan` read counts at each copy's edges) |
| `D` | one per differing tile pair between two copies of a repeat; `code` lists what differs: `S:a:b` span in bases, `P:a:b` phase, `E:a:b` edit count (with reads, plus per-copy depth/agreement and a verdict) |
| `L` | read-supported links between contig ends (within `-g` tiles, default 100), with junction length and sequence |
| `T` | (reads only) tiles where reads disagree with the assembly: `depth`, `agree`, break weights at SMEM edges, the assembly's bases, and the alternatives reads saw (same `S`/`P`/`E` codes, `B<`/`B>` = bases seen at a left/right SMEM break), each with its weight; alternatives below `--min` (default 1.0) are omitted |
| `G`, `X` | (`--trace`/`--trace-bed`) traced regions and, per region, every voting read placement: read, strand, query/reference tiles and bases, SMEM span, occurrences and vote weight. `--trace` traces the whole assembly; `--trace-bed` only the given 0-based BED regions |

```
tessellate map -i <ref.tbwt> -o <out.tsv> [-k <tiles>] [-O <occ>] [--frac <f>]
               [--top 5] [--gap 1000] [--band 64] [-g <gap>] [--vote] [--sr] reads.tq.gz ...
```

uses the same `.trep` as `hom` (building it if missing). For every read finds SMEMs against the index (`-k`/`-O` default to the values saved in `.trep`), and _projects_ anchors through the repeat table: a hit on one copy of a repeat is copied to every other copy. Tiles covered plus tiles whose exact geometry (phase, span, edits) matches the assembly is retained as anchors, and chained per contig and strand within `--band` tiles of diagonal drift and `--gap` tiles of gap. `--top` best chains are reported. (ties at the cutoff kept; 0 = all). With `-g N`, a read whose best chain beats the runner-up by at least `N` is settled early and only the best chain is written. `--vote` re-ranks a read's candidates by base-level (Myers) alignment votes. `--sr` adds extra seeds for short reads. `map` outputs a TSV with one row per candidate region:

| Column | Meaning |
|---|---|
| `read`, `rank`, `status` | read name, rank among its candidates, `best` or `secondary` |
| `reference`, `strand` | contig and strand |
| `query_tiles`, `query_bases` | aligned interval on the read (`start..end`) |
| `reference_tiles`, `reference_bases` | aligned interval on the contig |
| `covered_tiles`, `geometry_matches` | tiles covered by anchors / with exactly matching geometry |
| `d_sites`, `d_matches` | repeat-differing tiles covered / matched |
| `score`, `best_gap`, `best_ties` | chain score, margin to the next candidate (`*` if none), number of tied best candidates |
| `anchors`, `mean_rank`, `mapq` | anchors in the chain, Myers vote rank (`*` without `--vote`), mapping quality 0–60 |

```
tessellate polish --detect <qhom> --decide <traced qhom> --reads <reads.tq.gz>
                  --index <ref.tq.gz> --fasta <ref.fa> -o <polished.fa>
                  [--edits <edits.tsv>] [--windows <windows.tsv>] [options]
```

takes the T rows of the `--detect` report (`hom` with reads) where agreement over depth is below `--detect-agree` (default 0.5) with depth at least `--detect-depth` (default 3); each becomes a window padded by `--pad` tiles (default 2). `X` rows of the `--decide` report (with `hom --trace`), are read to render the read's bases across it and vote on the window's sequence: a window is edited when it has at least `--min-votes` reads (default 5), the winning sequence has at least `--min-support` votes (default 2), and depth is within `--max-depth` times the median (default 2). With `--copy-number`, extra repeat copies that the `--decide` `R` rows show to be unsupported (`--cn-*` options) are removed. The same reads can serve as both `--detect` and `--decide`, as in the example. `polish` outputs polished FASTA (`-o`), one row per applied edit (`--edits`, with rows `contig start end kind old_len new votes support`), and one row per window with its outcome, vote counts and the distribution of voted lengths (`--windows`).
